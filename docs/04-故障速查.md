# 04 · 故障速查

> 用法：`Ctrl+F` 直接搜错误信息的**关键词**（英文报错原样贴，便于匹配）。

## 30 秒定位法

| 现象 | 先看哪里 |
|---|---|
| 网页翻译完全不动 | 两个黑窗口还在吗 → [D 网关](#d-网关-8000) / [E 插件](#e-插件) |
| 某段变成英文原文 | 网关窗口有 `[fallback]` 吗 → [D 网关](#d-网关-8000) |
| 插件弹出错误小面板 | 长段落？→ [D §长段落](#2-长段落触发重试并回退原文) |
| 启动就报错、窗口闪退 | [B llama.cpp](#b-llamacpp-安装与启动) / [G Windows 脚本](#g-windows-脚本与编码) |
| 下载卡住 / 超时 | [F 网络](#f-网络与下载) |

## B. llama.cpp 安装与启动

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报缺 `cudart64_12.dll` / `cublas64_12.dll` | `cudart-*` 包没解压到同目录 | 两个 zip 都要解压到 `D:\ai\llama`，遇到同名选"替换" |
| 直接报"找不到 llama-server.exe" | zip 内是 `build\bin\...` 结构 | 进子目录全选剪切，粘到 `D:\ai\llama` 根目录 |
| `cudaErrorInsufficientDriver` | 驱动版本低于构建所用 CUDA | 更新 NVIDIA 驱动，或换更低 CUDA 版本的包 |
| 缺 `VCRUNTIME140.dll` / `MSVCP140.dll` | 缺 MSVC 运行库 | 装 **Microsoft Visual C++ 2015–2022 Redistributable (x64)** |
| `--list-devices` 只列 CPU | 下成了 `-bin-win-cpu-` 包 | 删掉重下 `-bin-win-cuda-12.4-` |
| `[!] 输出 --version 失败` | 新版 llama.cpp 已移除该参数 | **无害**，用 `--list-devices` 验证 |
| 显存不足 / OOM | 上下文或并发过大 | `-c 12288` → `-c 8192`；`--parallel 2` 不要提到 3+ |

**CORS 安全提示**（`WARNING: server default port will be changed to :9931` 等）→ **无害**，见文末白名单。

## C. 模型文件

| 现象 | 原因 | 处理 |
|---|---|---|
| 下到一半卡死 | 连接僵死 | `Ctrl+C` 后**原命令重跑**，会自动续传 |
| 启动时报 GGUF 解析错误 | 文件被截断 | 校 sha256 |
| 不确定文件是否完整 | — | 见下方校验命令 |

**校验（镜像 API 的字段是 `lfs.oid`，不是 `lfs.sha256`）**

```powershell
$t = curl.exe -sL "https://hf-mirror.com/api/models/Qwen/Qwen3-8B-GGUF/tree/main" | ConvertFrom-Json
"official: " + ($t | Where-Object { $_.path -eq 'Qwen3-8B-Q4_K_M.gguf' }).lfs.oid
"local   : " + (Get-FileHash D:\ai\mt\models\Qwen3-8B-Q4_K_M.gguf -Algorithm SHA256).Hash.ToLower()
```

正确值：`d98cdcbd03e17ce47681435b5150e34c1417f50b5c0019dd560e4882c5745785`，大小 `5,027,783,488` 字节。

## D. 网关（8000）

### 1. 报 `502 Bad Gateway`

**原因**：系统/IE 代理 `127.0.0.1:7993` 被 httpx 读到，请求被转给了代理。

**处理**：确认补丁存在

```powershell
Select-String -Path D:\ai\mt\local-mt-gateway.py -Pattern 'trust_env'
```

必须有两行 `httpx.AsyncClient(timeout=TIMEOUT, trust_env=False)`。

> 为什么只有 Python/httpx 中招、curl 没事：httpx 的 `trust_env=True` 会经
> `urllib.request.getproxies()` 回退读取 Windows 注册表里的 IE 代理设置，curl 不读。

### 2. 长段落触发重试并回退原文

**表现**：短句正常，**3 句以上的段落**整段变成英文，插件可能弹出错误面板。

**原因**：网关 v1.0 的句数检测要求句末标点后跟空格 —— 中文句号后面没有空格，导致误判为"截断"。

**处理**：确认 P2 补丁存在

```powershell
Select-String -Path D:\ai\mt\local-mt-gateway.py -Pattern 'o <= max'
```

应输出 `if s >= 3 and o <= max(1, s // 3):`

### 3. 网关窗口输出

| 日志行 | 含义 | 要不要处理 |
|---|---|---|
| `[retry] missing:[[ph0]]` | 模型吞了占位符，正在重试 | 偶发不用管；频繁则降 `TEMP` 到 0 |
| `[retry] truncated / too_short` | 检测到漏译，正在重试 | 偶发不用管 |
| `[fallback] 两次均不合格，回退原文` | **保底生效**，返回英文原文（不会吐坏数据） | 频繁出现要查原因 |
| `[err] backend: ...` | 后端调用失败 | 看模型窗口是否还活着 |
| `[harvest] +N` | 后台抽取了 N 个术语 | 正常 |

| 现象 | 原因 | 处理 |

| 整页都不翻译 | 服务没选对 / 网关没起 | 确认选的是「本地 Qwen3」，且 `http://127.0.0.1:8000/health` 通 |

## G. Windows 脚本与编码

| 现象 | 原因 | 处理 |
|---|---|---|
| `.ps1` 报 `数组索引表达式丢失或无效` / `字符串缺少终止符` | 文件是 **UTF-8 无 BOM**，PS 5.1 按 GBK 解码，中文变乱码破坏语法 | 存成 **UTF-8 with BOM**；或改用纯 ASCII 提示的脚本 |
| `out-file : 要求 FileStream 打开一个不是文件的设备` | PowerShell 不认 `nul`（那是 cmd 的写法） | 用 `> $null` 或 `\| Out-Null` |
| 双击 bat 一闪而过 | 程序报错后窗口自动关闭 | bat 末尾加 `pause` |
| 双击 bat 完全没反应 | 文件名实际是 `xxx.bat.txt` | 资源管理器 → 查看 → 勾选**文件扩展名**，重命名 |
| `.py` 里的中文变乱码 | 保存成了 GBK | 存成 UTF-8；验证：<br>`D:\Python\Python313\python.exe -X utf8 -c "s=open(r'D:\ai\mt\local-mt-gateway.py',encoding='utf-8').read();print('OK' if '你是技术文档翻译引擎' in s else 'BAD')"` |

## 一条命令搞定大部分体检

```powershell
Write-Host "== 端口 =="
curl.exe -s http://127.0.0.1:8000/health
curl.exe -s -o NUL -w "`n8080 -> %{http_code}`n" http://127.0.0.1:8080/v1/models
Write-Host "== 显存 =="
nvidia-smi --query-gpu=memory.used,memory.free --format=csv
Write-Host "== 补丁 =="
Select-String -Path D:\ai\mt\local-mt-gateway.py -Pattern 'trust_env|o <= max' | ForEach-Object { $_.Line.Trim() }
Write-Host "== 最近日志 =="
Get-Content D:\ai\mt\logs\gateway.log -Tail 15
```
