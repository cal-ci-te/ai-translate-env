# 02 · 沉浸式翻译配置

## 一、安装

| 浏览器 | 地址 |
|---|---|
| Chrome | `https://chromewebstore.google.com/` 搜「沉浸式翻译」 |
| Edge | `https://microsoftedge.microsoft.com/addons/` 搜「沉浸式翻译」 |

## 二、添加自定义翻译服务

路径：点工具栏插件图标 → **设置** → 左侧 **翻译服务** → **添加自定义翻译服务** → 类型选 **OpenAI**

### 必填项

| 字段 | 值 | 说明 |
|---|---|---|
| 自定义翻译服务名称 | `本地 Qwen3` | 任意 |
| 自定义 API 接口地址 | `http://127.0.0.1:8000/v1/chat/completions` | **必须**以 `/v1/chat/completions` 结尾 |
| APIKEY | `local` | 网关不校验，任意非空值 |
| 模型 | `qwen3-8b` | 与 `--alias` 一致 |
| 每秒最大请求数 | `4` | 与模型服务 `--parallel 2` 配合 |
| 每次请求最大文本长度 | `1000` | 单位＝字符；过大响应变慢 |
| **每次请求最大段落数** | `1` | **必须为 1**，否则批量分隔符易错位 |
| **流式输出** | **关闭** | 漏译检测与自动重试的前提 |
| Temperature | `0` | 无所谓，网关忽略此值（固定用 0.2） |
| 启用富文本翻译 | 关闭 | 减少不确定性 |
| 启用 AI 智能上下文 | **关闭** | 实验功能，会给单次请求塞超长上下文 |

### 提示词模板（很重要）

「**单段提示词**」「**多段提示词**」「**Subtitle Prompt**」三处，内容**全部改成只有**：

```
{{text}}
```

**原因**：插件发给网关的请求里，「单段提示词」是 **user 消息的模板**。
如果它保留默认的：

```
Translate to {{to}} (output translation only):
{{text}}
```

那句英文指令就会被当成"待翻译正文"的一部分送进模型，译文里可能混入
"翻译为中文（仅输出译文）：……" 这类废话。目标语言由网关统一控制（固定 `zh-CN`）。

**「系统提示词」不用改** —— 网关会丢弃插件发来的 system 消息，只取最后一条 user 消息。

## 三、显示模式（可选择是否显示原文）

设置里找「显示模式」：

| 模式 | 用途 |
|---|---|
| **双语对照**（上原文下译文） | 日常推荐，方便核对 |
| 仅译文 | 沉浸阅读 |
| 仅原文 | 临时看原始内容 |

再打开「**鼠标悬停显示原文**」，即可"平时只看译文，想看原文随时看"。

**快捷键**：地址栏输入 `chrome://extensions/shortcuts`（Edge 为 `edge://extensions/shortcuts`），
可给「翻译/还原」「切换显示模式」设快捷键。

## 四、验收清单（上真网页后逐条查）

| # | 怎么查 | 通过标准 |
|---|---|---|
| 1 | 找一段代码，和原文逐字比对 | **完全一致** |
| 2 | 页面 `Ctrl+F` 搜 `--verbose`、`API_KEY` | **能搜到** |
| 3 | 看正文 | 是中文，且没有整段消失 |
| 4 | 读几页后访问 `http://127.0.0.1:8000/glossary` | `learned` 里开始积累术语 |

## 五、已知限制

### `<pre>` / `<code>` 里的内容不翻译（插件设计如此）

插件为避免误翻代码，**默认跳过 `<pre>`、`<code>` 标签内的内容**。
副作用：**GitHub 的 commit message 正文**（多行描述部分）恰好用 `<pre>` 渲染，因此被一并跳过。

临时解法：

- **划词翻译**：选中该段正文 → 点翻译按钮（零配置）
- **悬停翻译**：鼠标停在正文上，用悬停快捷键

根治解法见 `03-项目配置.md` 的「已知问题」一节。

### 长段落曾被误判为"截断"

网关 v1.0 的句数检测要求中文句号后跟空格，导致 3 句以上段落全部触发重试并回退原文
（表现为插件弹出错误面板）。**v1.1 已修复（补丁 P2）**，症状为：短句正常、长段落变英文或弹窗。
